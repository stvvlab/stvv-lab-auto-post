# STVV LAB 投稿承認・自動予約フロー 01

## 目的
公式情報を根拠に投稿本文と画像を準備し、ユーザー確認を経て既存GitHub→Buffer→Xへ安全に連携する。自動予約の安定稼働と、公開結果の区別を両立する。

## 確認済みの現行実装（2026-11-12）
- .github/workflows/main.yml: schedule は 08:00 / 18:00 / 23:00 JST の3枠。STVV_ADVANCE_RESERVATIONS=true。
- preparation_inventory.py: 投稿候補のオフライン準備。チャットへの送信・ユーザー承認を自動化するものではない。
- editorial/imagegen_cards.json: reviewed、status、画像パス等の既存承認メタデータを持つ。
- advance_reservations.py: reviewed済み候補の公式本文・画像・重複・Buffer予約枠を確認して予約。予約済み≠送信済み≠X表示確認。
- delivery_run.py: 6時間超過の遅延実行は停止。停止時に新規送信しない。

## 目標フロー
1. 投稿候補を公式一次情報から生成。出典URL・対象時刻・本文・画像・画像ハッシュを一組で保存。
2. チャットで本文と画像をプレビュー。承認前の候補はBufferに送らない。
3. ユーザーが承認した正確な本文・画像ハッシュ・対象枠を記録。変更があれば再承認。
4. 既存の予約処理で重複防止・鮮度・公式情報・Buffer枠・画像同一性を確認。
5. Bufferの予約ID、予定日時、予約状態を記録。
6. Buffer送信状態を照会し、X本文・画像の公開表示は独立に確認。確認できない場合は「未確認」とする。
7. 失敗・不明時は自動再送しない。理由と次の対応を記録。

## 実装前の接続確認
- GitHub Actionsからこの既存チャットへ直接メッセージを送信し、承認を受信できる正式な連携経路は未確認。GitHubだけではこのチャットへの自動投稿は保証できない。
- 連携不可の場合は、GitHubに投稿プレビュー成果物（本文、画像URL、出典、ハッシュ）を保存し、ChatGPTの定期タスク等でその成果物を読み取って提示する方式を検討する。定期タスクの通知と同一チャットへの自動書き込みは別機能として検証する。
- 承認操作を機械判定できる識別子・権限・期限を設計する。会話内の曖昧な「よろしく」を自動送信承認に流用しない。

## 変更・検証方針
- 本ブランチは設計段階。予約処理・既存スケジュール・本番認証情報・投稿履歴を変更しない。
- まず読み取り専用プレビューを実装し、候補本文・画像と既存カードの一致をテスト。
- 次に明示承認から既存 reviewed メタデータへの橋渡しを検証。Buffer送信はモックでテストし、本番は別途確認。
- 6時間遅延の原因は Actions run creation/job start/scheduled slot の時刻を照合して別途調査する。安全停止は解除しない。
