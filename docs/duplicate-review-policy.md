# STVV LAB: 重複と新情報の審査（2026-10-29）

## 判定は4つの別の問題

1. **公式情報の真偽・鮮度**：一次資料の本文・日付・試合日時・選手記録を検証する。公式が過去に掲載しただけで、STVV LABの投稿済みとはしない。
2. **STVV LABでの公開・送信状態**：`publication_log`（送信確認）、`pending_posts`（送信結果不明）、`reserved_posts`（予約・取消・エラー）を別々に扱う。単なる`news`収集履歴は公開証拠ではない。
3. **編集上の重複**：同じ本文の再利用は期間を問わず禁止。同じ出典・試合を7日以内に再利用する場合は、現行では確認済みの新しい比較データか、厳格に審査された別事実のみ許可する。同じURL＝同じ話題とは限らないため、将来は投稿種別＋試合ID＋段階＋事実IDの明示的な審査を追加する。
4. **配信可否**：承認済み本文・画像SHA256・公式本文・予約先・Bufferの状態を確認。画像欠落、未承認、送信不明、取消済み、重複があれば送らない。Bufferの`scheduled`や`sent`だけでX表示済みとは呼ばない。

## 今回の実装範囲

- `content_guard.duplicate_reason`は公式`news`をX公開履歴として数えない。
- 7日を超えた**同一本文**も重複として拒否。
- 古い**pending／予約取消／送信結果不明**を期間切れで無視しない。新しいシュート数などを付けても自動再送を許さない。
- Bufferで`sent`確認済みかつ公開履歴に一致する予約は、送信待ちとして二重計上しない。
- 同じ記事から異なる事実を広く自動許可する変更は**まだ行っていない**。その判定には一次情報の具体的な引用、投稿意図、事実ID、X履歴との突合が必要。
